The loop

How RepoScope works

RepoScope is a CodeAct agent. Instead of choosing from a fixed menu of tools, its action is code: the model writes a JavaScript program, runs it in a real sandbox, observes the output, and repeats until it can answer.

  1. 1
    You ask. Name a repository and a question — architecture, dependencies, recent changes, testing, licensing, a specific module, or a comparison.
  2. 2
    The model writes code. It fetches repository metadata and file contents from GitHub, filters the tree, reads manifests and source, and prints compact evidence to stdout.
  3. 3
    A private Wasm sandbox runs it. The ts-sandbox component is private to this Spin app. It has no filesystem, no shell, no process spawning, and no Node APIs. Egress is allow-listed to api.github.com and raw.githubusercontent.com only.
  4. 4
    The output loops back. stdout, stderr, and errors become the model's observation. It fixes and re-runs, or writes a cited answer from what it actually saw.

Why code?

One program can fetch, parse, filter, count, and compare in a single step. That means fewer round-trips and answers computed from real data instead of guessed by the model.

What it can't do

It cannot access private repositories, authenticate to GitHub, read your machine, or reach arbitrary hosts. Unauthenticated GitHub API calls are rate limited, so very broad questions may stop early.

Built with Spin, the Spin Code Sandbox, and the CodeAct pattern.
